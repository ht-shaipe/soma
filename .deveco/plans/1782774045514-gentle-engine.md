# 对接国内 AI 视频生成 API

## Goal

为 soma 项目新增 AI 视频生成能力，用户可以选择使用 AI 模型根据脚本文案直接生成视频画面，替代目前的素材拼接方式。对接三家国内可访问的服务：**智谱 CogVideoX**（有免费模型）、**可灵 Kling**、**MiniMax 海螺**。

## Scope / Non-goals

**包含：**
- 三家 AI 视频生成 API 的 Rust 适配器实现
- 异步任务创建 → 轮询 → 下载视频的完整流程
- 配置项扩展（API Key、模型选择等）
- 前端配置界面和素材源选择
- pipeline 集成：当 `video_source` 设为 `cogvideox`/`kling`/`minimax` 时调用 AI 生成

**不包含：**
- 图生视频 (Image2Video) 功能（仅文本生视频）
- 视频延长 (Video Extend) 功能
- AI 生成视频的后期编辑功能
- 本地部署的开源视频模型（如 CogVideoX 开源版）

## Current State And Constraints

### 现有架构
- `soma-stock` crate 负责素材搜索和下载，已有 `SomaStockProvider` trait 和 Pexels/Pixabay/Coverr 实现
- `pipeline.rs` 的 `get_video_materials` 根据 `video_source` 路由到不同素材源
- 配置通过 `conf/config.toml` + 全局 `Config` 缓存管理
- 前端 `videoSource` 在 `videoParams` store 中，默认 `pexels`

### AI 视频生成的关键差异
与素材搜索不同，AI 视频生成是**异步耗时操作**（通常 2-5 分钟），需要：
1. 提交生成任务 → 获得 task_id
2. 轮询任务状态 → 等待完成
3. 下载生成的视频文件

这意味着 pipeline 中的素材获取步骤会变慢很多，需要合理设置超时和进度反馈。

### 2. 核心 Trait 设计

```rust
// aivideo/mod.rs
#[async_trait(?Send)]
pub trait AiVideoProvider: Send + Sync {
    /// 提交文本生成视频任务，返回任务 ID
    async fn create_task(&self, params: &VideoGenParams) -> Result<String, SomaError>;
    
    /// 查询任务状态，返回 (状态, 视频下载URL列表)
    async fn query_task(&self, task_id: &str) -> Result<VideoGenStatus, SomaError>;
    
    /// 下载生成的视频到本地
    async fn download_video(&self, url: &str, save_path: &str) -> Result<String, SomaError>;
}

pub struct VideoGenParams {
    pub prompt: String,           // 脚本段落描述
    pub aspect_ratio: String,     // "16:9" / "9:16" / "1:1"
    pub duration: u32,            // 视频时长（秒）
    pub model: Option<String>,    // 模型名称（可选，用默认）
}

pub enum VideoGenStatus {
    Processing,
    Success { video_urls: Vec<String> },
    Failed { message: String },
}
```

### 3. 三家 API 适配器要点

#### 智谱 CogVideoX
- **端点**: `POST https://open.bigmodel.cn/api/paas/v4/videos/generations`
- **轮询**: `GET https://open.bigmodel.cn/api/paas/v4/async-result/{id}`
- **认证**: `Authorization: Bearer {api_key}`（复用已有的 `zhipu_api_key`）
- **免费模型**: `cogvideox-flash`（0元/次）
- **付费模型**: `cogvideox-3`（1元/次，支持 5s/10s，4K）
- **分辨率映射**: "16:9"→"1920x1080", "9:16"→"1080x1920", "1:1"→"1024x1024"

#### 可灵 Kling
- **端点**: `POST https://api-singapore.klingai.com/v1/videos/text2video`
- **轮询**: `GET https://api-singapore.klingai.com/v1/videos/text2video/{id}`
- **认证**: JWT (HS256)，需 AccessKey + SecretKey 生成 token
- **模型**: `kling-v2-master`（默认）、`kling-v2-1-master`
- **分辨率**: 通过 `aspect_ratio` 字段指定 "16:9"/"9:16"/"1:1"
- **注意**: JWT 生成需要 `jsonwebtoken` crate

#### MiniMax 海螺
- **端点**: `POST https://api.minimaxi.com/v1/video_generation`
- **轮询**: `GET https://api.minimaxi.com/v1/query/video_generation?task_id={id}`
- **文件获取**: `GET https://api.minimaxi.com/v1/files/retrieve?file_id={id}`
- **认证**: `Authorization: Bearer {api_key}`
- **模型**: `MiniMax-Hailuo-2.3`（默认）
- **定价**: 768P/6s ¥2, 1080P/6s ¥3.5
- **注意**: 两步获取视频（先查任务获取 file_id，再用 file_id 获取下载链接）

### 5. Pipeline 集成

修改 `pipeline.rs` 的 `get_video_materials`，增加 AI 视频生成分支：

```rust
fn get_video_materials(...) -> Result<Vec<String>, SomaError> {
    let source = params.video_source.as_deref().unwrap_or("pexels");
    
    match source {
        "cogvideox" | "kling" | "minimax" => {
            // AI 视频生成模式
            generate_ai_videos(task_id, params, terms, audio_duration, conf, source)
        }
        "local" => { /* 现有逻辑 */ }
        _ => { /* 现有 Pexels/Pixabay/Coverr 逻辑 */ }
    }
}
```

AI 视频生成流程：
1. 将脚本的每段（按 `paragraph_number` 分）作为 prompt
2. 为每段提交 AI 视频生成任务
3. 轮询所有任务直到完成
4. 下载生成的视频到任务目录
5. 返回视频路径列表（与素材下载返回格式一致）

### 6. 进度反馈

AI 视频生成耗时较长（2-5分钟/段），需要在轮询过程中更新任务进度：
- 提交阶段：进度 40% → 45%
- 轮询阶段：进度 45% → 48%（按完成比例递增）
- 下载阶段：进度 48% → 50%

## Risks And Compatibility

1. **API 变更风险** — 三家 API 可能迭代，需要关注文档更新。应对：将 API 细节封装在各适配器内部
2. **生成耗时** — AI 视频每段 2-5 分钟，5 段脚本可能需要 10-25 分钟。应对：合理设置超时（默认 300s），进度实时反馈
3. **并发限制** — 智谱并发 5、Kling 并发 1。应对：串行提交任务，避免触发限流
4. **成本控制** — 付费模型按次计费。应对：默认推荐免费模型 cogvideox-flash，前端提示费用
5. **Kling JWT 认证** — 需要额外引入 jsonwebtoken 依赖。已在设计中考量
6. **视频 URL 有效期** — 生成的视频下载链接有时效（智谱/MiniMax 约 1 小时）。应对：生成后立即下载

## Rollback

所有改动都在新增模块和扩展点，不影响现有功能。回滚方式：
1. 删除 `soma-stock/src/aivideo/` 目录
2. 还原 `soma-stock/src/lib.rs` 的 aivideo 导出
3. 还原 `config.rs` 的新增配置项
4. 还原 `pipeline.rs` 的 AI 视频分支持
5. 还原前端改动
6. `video_source=pexels` 时完全不受影响
