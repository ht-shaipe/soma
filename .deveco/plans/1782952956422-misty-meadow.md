# 视频生成大模型接口整合计划

## Goal

将 Soma 项目中 `soma-stock/src/aivideo/` 模块的视频生成能力（智谱 CogVideoX、可灵 Kling、MiniMax 海螺）整合到 `ai-llm-kit` 的 `LlmMultimodalService` 体系中，实现：
- 所有视频生成 API 适配器集中在 `ai-llm-kit` 维护
- Soma 通过 `ai-llm-kit` 的统一接口调用视频生成服务
- 消除智谱视频生成的重复实现

## Scope / Non-goals

**包含：**
- 在 `ai-llm-kit/llm/src/` 下新增 `kling/` 和 `minimax/` 多模态适配器模块
- 修正 `ai-llm-kit` 中智谱视频适配器，使其兼容 Soma 已有的更完整实现
- 扩展 `VideoGenerationParams` 和 `VideoGenerationResult` 以满足 Soma 业务需求
- 重构 Soma 的 `soma-stock/src/aivideo/` 为薄桥接层，调用 `ai-llm-kit` 接口
- 在 `LlmFactory`/`LlmProvider` 中注册 Kling 和 MiniMax

**不包含：**
- 不修改 `LlmService` trait（对话接口）
- 不修改 Soma 视频流水线 `pipeline.rs` 的业务逻辑
- 不重构 Soma 的素材搜索（Pexels/Pixabay/Coverr）部分

## Current State And Constraints

### 重复实现对比

| 提供商 | Soma (`soma-stock/aivideo/`) | AI Kit (`ai-llm-kit/llm/src/`) |
|---|---|---|
| 智谱 CogVideoX | `zhipu.rs` — AiVideoProvider trait | `zpu/multimodal.rs` — LlmMultimodalService trait |
| 可灵 Kling | `kling.rs` — AiVideoProvider trait | ❌ 未接入 |
| MiniMax 海螺 | `minimax.rs` — AiVideoProvider trait | ❌ 未接入 |
| 通义万相 | ❌ | `qw/multimodal.rs` ✅ |
| 混元 | ❌ | `hy/multimodal.rs` ✅ |
| 豆包/即梦 | ❌ | `dbao/jimeng.rs` ✅ |

### Soma 的 aivideo 调用链
```
soma-stock/src/lib.rs::generate_ai_videos()
  → aivideo::create_provider(source, conf)
  → provider.create_task(&VideoGenParams)
  → aivideo::poll_until_done(provider, task_id, timeout, interval)
  → provider.download_video(url, save_path)
```

### AI Kit 的多模态调用链
```
某Llm实例.multimodal() → Box<dyn LlmMultimodalService>
  → .generate_video(&VideoGenerationParams) → VideoGenerationResult
  → .query_video_task(task_id) → VideoGenerationResult
```

### 关键差异
- Soma 的 `AiVideoProvider` 有 `download_video()` 方法，AI Kit 的 `LlmMultimodalService` 没有
- Soma 用自己的 `VideoGenParams`/`VideoGenStatus`，AI Kit 用 `VideoGenerationParams`/`VideoGenerationResult`
- Soma 有 `poll_until_done()` 通用轮询逻辑
- 可灵需要 JWT(HS256) 认证，当前依赖 `hmac` + `sha2` crate
- MiniMax 有特殊的两步获取流程（task → file_id → download_url）

### 依赖关系
- Soma workspace 已依赖 `ai-llm-kit`（通过 `soma-server`）
- `soma-stock` 当前**不依赖** `ai-llm-kit`
- `ai-llm-kit` 当前**不依赖** `hmac`/`sha2`

## Design

### 第1步：扩展 ai-llm-kit 的 multimodal 类型

在 [llm/src/multimodal.rs](llm/src/multimodal.rs) 中：

1. **扩展 `VideoGenerationParams`**：
   - 新增 `aspect_ratio: Option<String>` — Soma 用 "16:9" 格式，而 AI Kit 用 "1920x1080"
   - 新增 `prompt_optimizer: Option<bool>` — MiniMax 需要
   - 保持现有字段不变

2. **扩展 `VideoGenerationResult`**：
   - 新增 `video_urls: Vec<String>` — 部分厂商返回多个视频 URL（智谱/可灵）
   - 保留 `url: Option<String>` 向后兼容（取 `video_urls.first()`）

3. **新增 `VideoDownloadExt` trait**（可选扩展）：
   ```rust
   #[async_trait(?Send)]
   pub trait VideoDownloadExt: Send + Sync {
       async fn download_video(&self, url: &str, save_path: &str) -> Result<String>;
   }
   ```
   提供默认实现（通用 HTTP 下载），可灵/MiniMax 等无需特殊处理

4. **新增 `poll_video_task()` 通用轮询辅助函数**：
   ```rust
   pub async fn poll_video_task(
       service: &dyn LlmMultimodalService,
       task_id: &str,
       timeout: u64,
       interval: u64,
   ) -> Result<VideoGenerationResult>
   ```

### 第2步：新增可灵 Kling 适配器

新建 [llm/src/kling/](llm/src/kling/) 目录：

```
kling/
├── mod.rs          # Kling 主结构 + LlmService 实现
└── multimodal.rs   # KlingMultimodal 实现 LlmMultimodalService
```

关键点：
- `Kling` 结构体持有 `access_key` + `secret_key` + `model`
- JWT 认证使用 `hmac` + `sha2`（需在 `llm/Cargo.toml` 添加依赖）
- `LlmProvider` 枚举新增 `Kling = 11`
- 实现 `MultimodalGenerationExt for Kling`

### 第3步：新增 MiniMax 海螺适配器

新建 [llm/src/minimax/](llm/src/minimax/) 目录：

```
minimax/
├── mod.rs          # MiniMax 主结构 + LlmService 实现
└── multimodal.rs   # MinimaxMultimodal 实现 LlmMultimodalService
```

关键点：
- `MiniMax` 结构体持有 `api_key` + `model`
- `query_video_task` 中需实现两步获取（task → file_id → download_url）
- `LlmProvider` 枚举新增 `MiniMax = 12`
- 实现 `MultimodalGenerationExt for MiniMax`

### 第4步：修正智谱视频适配器

修改 [llm/src/zpu/multimodal.rs](llm/src/zpu/multimodal.rs)：

- `generate_video` 中增加 `duration` 参数传递（当前 Soma 的 zhipu.rs 有 `duration` 支持，AI Kit 的缺失对 cogvideox-3 的 duration 请求体构建）
- `query_video_task` 中使用 `/async-result/` 路径（Soma 版本更准确）
- 确保 `VideoGenerationResult.video_urls` 正确填充

### 第5步：更新 LlmFactory / LlmProvider

修改 [llm/src/factory.rs](llm/src/factory.rs)：
- `LlmProvider` 枚举新增 `Kling = 11` 和 `MiniMax = 12`
- `LlmFactory::create()` 新增对应分支
- `supported_providers()` 列表新增

修改 [llm/src/lib.rs](llm/src/lib.rs)：
- 新增 `mod kling;` 和 `mod minimax;`

### 第6步：重构 Soma 的 aivideo 模块

修改 [soma-stock/Cargo.toml](crates/soma-stock/Cargo.toml)：
- 添加 `ai-llm-kit = { workspace = true }` 依赖
- 移除 `hmac` 和 `sha2` 依赖（已移至 ai-llm-kit）

修改 [soma-stock/src/aivideo/mod.rs](crates/soma-stock/src/aivideo/mod.rs)：

**保留**：
- `VideoGenParams` / `VideoGenStatus` — 业务层类型不变
- `AiVideoProvider` trait — 作为内部桥接接口
- `poll_until_done()` — 轮询逻辑
- `download_video_common()` — 下载逻辑
- `create_provider()` — 工厂函数

**改造**：
- `ZhipuVideo` → 内部持有 `ZhipuMultimodal`，委托调用
- `KlingVideo` → 内部持有 `KlingMultimodal`，委托调用
- `MinimaxVideo` → 内部持有 `MinimaxMultimodal`，委托调用
- 三个适配器文件（zhipu.rs / kling.rs / minimax.rs）改为薄包装层

桥接逻辑示例（以 zhipu.rs 为例）：
```rust
pub struct ZhipuVideo {
    multimodal: ZhipuMultimodal,
    model: String,
}

impl ZhipuVideo {
    pub fn new(api_key: &str, model: &str) -> Self {
        Self { multimodal: ZhipuMultimodal::new(api_key), model: model.to_string() }
    }
}

impl AiVideoProvider for ZhipuVideo {
    async fn create_task(&self, params: &VideoGenParams) -> Result<String, SomaError> {
        let mm_params = VideoGenerationParams {
            model: self.model.clone(),
            prompt: params.prompt.clone(),
            size: Some(aspect_to_size(&params.aspect_ratio).to_string()),
            duration: Some(params.duration as i32),
            ..Default::default()
        };
        let result = self.multimodal.generate_video(&mm_params).await
            .map_err(|e| SomaError::VideoGen(format!("{:?}", e)))?;
        Ok(result.task_id)
    }
    // ...
}
```

**删除**：`soma-stock/src/aivideo/zhipu.rs` / `kling.rs` / `minimax.rs` 中的 HTTP 请求代码，替换为 `ai-llm-kit` 委托调用。

## Risks And Compatibility

1. **hmac/sha2 依赖**：`ai-llm-kit` 需新增 `hmac` + `sha2` 依赖，这些是纯 Rust 实现无系统依赖，风险低
2. **类型变更兼容性**：`VideoGenerationParams` 和 `VideoGenerationResult` 新增字段均为 `Option`，向后兼容
3. **智谱 API 路径差异**：Soma 用 `/async-result/{id}`，AI Kit 用 `/videos/result/{id}`，需验证哪个是最新正确路径
4. **LlmProvider 枚举值**：新增 `Kling = 11` 和 `MiniMax = 12`，不影响现有枚举值

## Rollback

- AI Kit 侧：所有新增文件独立，回滚只需删除 `kling/`、`minimax/` 目录和对应 mod 注册，恢复 `multimodal.rs` 原始内容
- Soma 侧：`aivideo/` 模块保留 `AiVideoProvider` trait 不变，回滚时恢复原始实现文件、移除 `ai-llm-kit` 依赖
- Git 分支策略：建议在 feature 分支上开发，合并前验证两个项目均可编译通过
