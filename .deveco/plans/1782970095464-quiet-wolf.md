# Pipeline Refactor: 6-Step → 7-Step Storyboard Pipeline

## Goal

Transform the video generation pipeline from a flat 6-step process into a structured 7-step process with storyboard/scene splitting, enabling per-scene visual prompts that dramatically improve AI video generation quality.

**Current flow:**
```
用户输入 → script(blob) → keywords(flat list) → audio → subtitle → materials → compose
```

**Target flow:**
```
用户输入 → ①需求理解 → ②文案/剧情 → ③分镜脚本+提示词(1 LLM call) → ④素材生成 → ⑤音频生成 → ⑥合成输出
```

Note: The user's diagram shows 7 steps but after merging storyboard+prompts into one LLM call and keeping subtitle within compose, the implementation becomes 6 pipeline steps with clearer semantics. The mapping is:

| User's Step | Pipeline Step | Implementation |
|---|---|---|
| ① 需求理解 | Step 1 | LLM refine/understand intent → structured subject |
| ② 文案/剧情 | Step 2 | LLM generate narration script |
| ③ 分镜脚本 + ④ 提示词生成 | Step 3 | **One** LLM call → StoryboardScene[] with visual_prompt per scene |
| ⑤ 素材生成 | Step 4 | Per-scene visual_prompt → AI video / stock search |
| ⑥ 音频生成 | Step 5 | Merge narrations → whole-text TTS + BGM |
| ⑦ 合成输出 | Step 6 | FFmpeg compose (includes subtitle generation) |

## Scope / Non-goals

**In scope:**
- New `StoryboardScene` data structure
- New LLM prompts for intent understanding, script generation, and storyboard+prompts generation
- Pipeline step reordering (audio moves after materials)
- Per-scene visual_prompt used for AI video generation
- `stop_at` values updated for new steps
- TaskUpdateData extended with storyboard field

**Out of scope:**
- Frontend UI changes (progress display update deferred)
- Per-scene split TTS (use merged narration approach)
- Camera movement / transition actually applied in FFmpeg (store in data model but don't act on it yet)
- New API endpoints

## Current State And Constraints

### Current pipeline (pipeline.rs)
1. `generate_script` (5%→10%) — LLM generates script blob, or uses user-provided script
2. `generate_terms` (10%→20%) — LLM extracts flat keyword list, or uses user-provided terms
3. `generate_audio` (20%→30%) — TTS generates audio from full script
4. `generate_subtitle` (30%→40%) — Whisper or Edge TTS subtitle generation
5. `get_video_materials` (40%→50%) — Pexels/Pixabay/AI video download using flat keywords
6. `generate_final_videos` (50%→100%) — FFmpeg compose with BGM, watermark, intro/outro

### Key constraints
- Pipeline runs in `std::thread` with `rt.block_on()` for async calls
- `#[async_trait(?Send)]` used throughout
- `TaskUpdateData` stores intermediate results (script, terms, audio_file, materials, etc.)
- `stop_at` parameter supports: "script", "terms", "audio", "subtitle", "materials"
- AI video generation uses `soma_stock::generate_ai_videos(task_id, terms, source, ...)` where `terms` is flat `&[String]`
- Stock video download uses `soma_stock::download_videos(task_id, terms, source, ...)` where `terms` is flat `&[String]`
- LLM calls go through `ai_llm_kit` factory with retry wrapper

## Design

### 1. New Data Structure: `StoryboardScene`

```rust
// In soma-core/src/models.rs

/// 分镜脚本的单个场景
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct StoryboardScene {
    /// 场景序号（从 1 开始）
    pub scene_id: u32,
    /// 场景描述/旁白文本（用于 TTS 和字幕）
    pub narration: String,
    /// 视觉提示词（用于 AI 视频生成或素材搜索）
    pub visual_prompt: String,
    /// 镜头运动：push_in / pull_out / pan_left / pan_right / tilt_up / tilt_down / static / zoom
    #[serde(default)]
    pub camera_movement: Option<String>,
    /// 场景时长（秒）
    #[serde(default)]
    pub duration: Option<u32>,
    /// 与下一场景的转场方式：cut / fade / dissolve / wipe
    #[serde(default)]
    pub transition: Option<String>,
}
```

### 2. LLM Prompt Design

#### Step 1: 需求理解 (Intent Refinement)
- **Input**: user's `video_subject` + optional `video_script_prompt`
- **Output**: structured subject description (enriched, clarified)
- **Prompt**: "你是一个视频创意策划专家。请根据用户的简短描述，提炼出清晰的视频主题、目标受众、情感基调和核心信息点。以JSON输出..."

This step is **lightweight** — if the user already provided a detailed script/prompt, it passes through. Only when the input is vague does it expand.

#### Step 2: 文案/剧情 (Script Generation)
- **Input**: refined subject from step 1
- **Output**: full narration script (similar to current `generate_script` output but structured for scene splitting)
- **Prompt**: Similar to current, but explicitly instruct LLM to output narration that naturally splits into scenes

#### Step 3: 分镜脚本 + 提示词 (Storyboard + Prompts — ONE LLM call)
- **Input**: narration script from step 2
- **Output**: `StoryboardScene[]` as JSON array
- **Prompt**:
```
你是一个专业的视频分镜导演。请根据给定的视频脚本文案，将其拆分为多个分镜场景，并为每个场景生成视觉提示词。

要求：
1. 每个场景对应一段旁白文本（narration），所有场景的narration合并后应还原原始脚本
2. visual_prompt 是该场景画面的英文视觉描述，要具体、有画面感，适合AI视频生成或素材搜索
3. camera_movement 从以下选择：push_in(推进), pull_out(拉远), pan_left(左摇), pan_right(右摇), tilt_up(上仰), tilt_down(下俯), static(固定), zoom(变焦)
4. duration 为该场景建议时长（秒），需与旁白长度匹配
5. transition 为该场景到下一场景的转场方式：cut(直切), fade(淡入淡出), dissolve(叠化), wipe(划变)

以JSON数组输出，格式：
[
  {
    "scene_id": 1,
    "narration": "场景旁白文本",
    "visual_prompt": "A woman walking through a sunlit forest, golden hour, cinematic, 4K",
    "camera_movement": "push_in",
    "duration": 5,
    "transition": "fade"
  }
]

只输出JSON数组，不要代码围栏或解释。
```

### 3. Pipeline Step Reordering

**New pipeline flow:**

```
Step 1: generate_intent      (0%→5%)    — LLM understand/refine intent
Step 2: generate_script      (5%→15%)   — LLM create narration script
Step 3: generate_storyboard  (15%→30%)  — LLM split into StoryboardScene[]
Step 4: get_video_materials  (30%→55%)  — Per-scene visual_prompt → AI/stock videos
Step 5: generate_audio       (55%→70%)  — Merge narrations → TTS + subtitle
Step 6: generate_final_videos (70%→100%) — FFmpeg compose
```

**Key changes:**
- Audio/subtitle generation moves from step 3/4 to step 5 (after materials)
- Subtitle generation merged into step 5 (it depends on audio, not on materials)
- `get_video_materials` now uses `storyboard[].visual_prompt` instead of flat `terms`
- Progress percentages adjusted: materials phase gets more weight (30%→55%) since AI video gen is the slowest part

### 4. How Materials Use Storyboard

Currently `generate_ai_videos(task_id, terms, ...)` takes flat `terms: &[String]`.

After refactor: extract `visual_prompt` from each `StoryboardScene` as the "terms":
```rust
let visual_prompts: Vec<String> = storyboard.iter()
    .map(|scene| scene.visual_prompt.clone())
    .collect();
soma_stock::generate_ai_videos(task_id, &visual_prompts, source, ...)
```

For stock video mode (Pexels/Pixabay), same approach — use `visual_prompt` as search keywords.

### 5. Audio Generation After Materials

```rust
// Step 5: Merge all scene narrations into one text
let full_narration: String = storyboard.iter()
    .map(|s| s.narration.as_str())
    .collect::<Vec<&str>>()
    .join(" ");

// Then TTS on full_narration (same as current logic)
let (audio_file, audio_duration) = generate_audio(task_id, params, &full_narration, &conf)?;

// Subtitle generation follows audio (same as current)
let subtitle_path = generate_subtitle(task_id, params, &full_narration, &audio_file, &conf)?;
```

### 6. Backward Compatibility

- `stop_at` values: add new values ("intent", "storyboard") while keeping old ones working
  - "script" → stops after step 2 (same semantic)
  - "terms" → stops after step 3 (storyboard replaces terms)
  - "audio" → stops after step 5
  - "subtitle" → stops after step 5
  - "materials" → stops after step 4
- If user provided `video_script` directly, skip step 1 and 2, go straight to step 3
- If user provided `video_terms` directly, convert them to a simple storyboard (each term → one scene)
- `TaskUpdateData.terms` renamed conceptually to `storyboard` but field kept for backward compat initially, adding new `storyboard` field

## Risks And Compatibility

- **LLM JSON reliability**: The storyboard LLM call returns JSON array. If parsing fails, fallback to current behavior (flat script + flat terms). Must add robust JSON parsing with fallback.
- **Storyboard quality**: Visual prompts quality depends on LLM model capability. Smaller models may produce vague prompts. Fallback: if `visual_prompt` is too short/generic, supplement with `narration` keywords.
- **Progress mapping change**: Frontend shows progress percentage — if it maps percentages to specific step names, the new mapping will be wrong. Since we're only changing backend, the frontend will just show different percentages at different times, which is acceptable.
- **Narration merge fidelity**: Merging scene narrations and then TTS-ing as one block should produce same audio as current approach since current approach also TTS-es the full script. Risk is minimal.
