# 数字人长视频分段生成：6 秒限制下的拼接策略与音画同步

> EchoMimicV3-Flash 单次最多生成 150 帧（6 秒 @25fps）。一段 30 秒的口播文案怎么生成？分段生成再拼接。但拼接后音画有 0.7 秒偏差，怎么对齐？本文记录完整的分段生成方案。

## TL;DR

```
文案 → 按标点切句 → 循环(TTS → 检查时长 → 超限则二次切分 → 口播视频 → tpad补齐) → FFmpeg concat → 叠字幕
```

实测：一段 33 秒文案切成 9 段，逐段生成后拼接，tpad 补齐后音画偏差 <0.1s，肉眼不可见。

## 问题

EchoMimicV3-Flash 有个硬限制：**单次推理最多 150 帧**。

25fps 下 150 帧 = 6 秒。也就是说，单次推理最多生成 6 秒的视频。

但实际口播文案通常 30-60 秒，远超 6 秒。怎么办？

**方案**：把文案切成多个短句，每句生成一段 6 秒以内的视频，最后用 FFmpeg 拼接。

听起来简单，但实际做起来有一堆问题：

1. 怎么切？按字数切还是按标点切？
2. 切完每句多长？TTS 合成的音频可能超 6 秒
3. 拼接后音画同步吗？
4. 拼接处的口型连续吗？

## 一、文案切分策略

### 第一刀：按标点切

```rust
pub fn split_into_segments(text: &str, max_chars: usize) -> Vec<String> {
    // 先按标点（。！？，；）切分
    let raw_segments = split_string_by_punctuations(text);
    
    // 合并过短的段，拆分过长的段
    let mut result = Vec::new();
    for seg in raw_segments {
        if seg.chars().count() > max_chars {
            // 过长：按字符数二次切分
            result.extend(split_long_segment(&seg, max_chars));
        } else {
            result.push(seg);
        }
    }
    result
}
```

`max_chars` 设为 15（中文约 15 字 = 5-6 秒语音）。

### 第二刀：按字符切（处理超长段）

有些文案没有标点（比如一长串产品介绍），需要按字符数切：

```rust
pub fn split_long_segment(text: &str, max_chars: usize) -> Vec<String> {
    let chars: Vec<char> = text.chars().collect();
    let mut result = Vec::new();
    let mut start = 0;

    while start < chars.len() {
        let end = (start + max_chars).min(chars.len());
        if end == chars.len() {
            result.push(chars[start..end].iter().collect());
            break;
        }

        // 优先在空格处断开
        let mut break_pos = end;
        for i in (start + 1..=end).rev() {
            if chars[i - 1] == ' ' {
                break_pos = i;
                break;
            }
        }
        result.push(chars[start..break_pos].iter().collect());
        start = break_pos;
    }
    result
}
```

**关键**：优先在空格处断开，避免把词语从中间切开（此优化仅对英文/中英混排生效，纯中文按固定字数切断）。

## 二、TTS 音频超 6 秒怎么办？

文案切分后，每句约 15 字。但 TTS 语速不同，15 字可能生成 5-8 秒音频。如果超过 6 秒，EchoMimicV3 还是会报错。

### 二次切分保护

```rust
const SINGLE_GEN_DURATION_LIMIT: f64 = 6.0;

fn process_segment(text: &str, ...) -> Result<SegmentResult, SomaError> {
    // TTS 合成
    let audio_path = generate_audio_to(...)?;
    let audio_duration = ffmpeg.get_audio_duration(&audio_path)?;
    
    // 检查是否超限
    if audio_duration > SINGLE_GEN_DURATION_LIMIT {
        // 二次切分：把这段文案再切成更短的
        let sub_segments = split_long_segment(text, 8); // 降到 8 字
        // 递归处理每个子段
        // ...
    } else {
        // 正常生成口播视频
        let video_path = generate_portrait_video(...)?;
        Ok(SegmentResult { audio_path, video_path, audio_duration })
    }
}
```

**实测**：15 字中文 TTS 音频约 4-6 秒，偶尔超 6 秒（语速慢的语音）。二次切分到 8 字后基本都在 4 秒以内。

## 三、FFmpeg 音频拼接

每段 TTS 音频单独生成后，需要拼接成完整音频：

```rust
fn concat_audios(&self, audio_files: &[String], output_file: &str) 
    -> Result<(), SomaError> 
{
    // 创建 concat 列表文件
    let list_content: String = audio_files
        .iter()
        .map(|f| format!("file '{}'\n", f))
        .collect();
    
    let list_file = output_file.replace(".wav", "_list.txt");
    std::fs::write(&list_file, &list_content)?;
    
    // FFmpeg concat
    self.run_simple(&[
        "-y", "-f", "concat", "-safe", "0",
        "-i", &list_file,
        "-c", "copy", output_file
    ])?;
    
    Ok(())
}
```

**坑**：`-c copy` 要求所有音频编码一致。如果 TTS 输出 MP3 而某段是 WAV，拼接会失败。**确保所有段用相同编码**。

## 四、口播视频拼接与冻结帧补齐

每段口播视频长度可能不一致（TTS 音频 5.2 秒 → 视频 5.0 秒，25fps 取整导致）。拼接后音画会有偏差。

### 问题分析

```
段1: 音频 5.2s → 视频 5.0s（125 帧）
段2: 音频 4.8s → 视频 4.7s（118 帧）
拼接后: 音频 10.0s → 视频 9.7s
偏差: 0.3s
```

多段累积后偏差可达 0.5-0.7 秒，肉眼可见的音画不同步。

### 解决方案：tpad 冻结帧补齐

用 FFmpeg 的 `tpad` 滤镜在每段视频末尾补冻结帧，把视频长度补齐到音频长度：

```bash
ffmpeg -y -i segment_0.mp4 \
    -i segment_0.wav \
    -filter_complex "[0:v]tpad=stop_mode=clone:stop_duration=0.2[v]" \
    -map "[v]" -map 1:a \
    -c:v libx264 -c:a aac \
    segment_0_padded.mp4
```

`tpad=stop_mode=clone:stop_duration=0.2`：在视频末尾克隆最后一帧，补 0.2 秒。

```rust
fn pad_video_to_audio_duration(
    ffmpeg: &Ffmpeg,
    video_path: &str,
    audio_path: &str,
    output_path: &str,
) -> Result<(), SomaError> {
    let video_dur = ffmpeg.get_video_duration(video_path)?;
    let audio_dur = ffmpeg.get_audio_duration(audio_path)?;
    let pad_dur = audio_dur - video_dur;

    if pad_dur <= 0.01 {
        // 不需要补齐
        std::fs::copy(video_path, output_path)?;
        return Ok(());
    }

    // tpad 补冻结帧
    let filter = format!(
        "tpad=stop_mode=clone:stop_duration={:.3}",
        pad_dur
    );
    ffmpeg.run_simple(&[
        "-y", "-i", video_path,
        "-vf", &filter,
        "-c:v", "libx264", "-c:a", "copy",
        output_path
    ])?;
    Ok(())
}
```

### 拼接流程

```
每段处理：
  1. TTS 合成音频
  2. EchoMimicV3 生成口播视频
  3. tpad 补齐视频到音频长度
  
最后拼接：
  4. FFmpeg concat 所有视频段
  5. FFmpeg concat 所有音频段
  6. 合并音视频 + 叠字幕 + BGM
```

## 六、HeyGem 方案对比

后来集成了 HeyGem（Duix.Avatar），它**没有 6 秒限制**：

| 维度 | EchoMimicV3 分段 | HeyGem 单段 |
|------|-----------------|-------------|
| 长视频 | 需切分+拼接 | 原生支持 |
| 音画同步 | 需 tpad 补齐 | 精确同步 |
| 拼接缝隙 | 有（冻结帧） | 无 |
| 生成速度 | 串行 N 段 | 单次 |
| 代码复杂度 | 高（切分+拼接+补齐） | 低 |

HeyGem 由音频驱动口型，单段即可保证音画同步，不需要分段。但需要常驻 GPU 服务器 + Docker。

**结论**：如果用 EchoMimicV3，分段方案可以工作但有 0.1-0.7s 偏差；如果追求完美音画同步，用 HeyGem。

## 总结

分段生成的核心逻辑：

```
切句 → 循环(TTS → 检查时长 → 二次切分 → 口播视频 → tpad补齐) → FFmpeg concat → 叠字幕
```

关键点：

1. **按标点切，超长再按字符切**
2. **TTS 音频超 6 秒要二次切分**
3. **tpad 冻结帧补齐音画偏差**
4. **拼接用 FFmpeg concat，确保编码一致**

代码约 400 行。不完美但可用，是 EchoMimicV3 限制下的最优解。
